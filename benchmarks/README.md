# Контрольные задачи и сравнение стратегий

`suite.json` содержит четыре выпуклые 2D-области в миллиметрах. Изделие
имеет размер 300 × 100 мм, пропилы и припуски нулевые, повороты произвольные.

Запуск из корня установленного проекта:

```sh
python -m rockcut.benchmark --seconds 20 --seeds 101,202,303 --variants baseline,combined --workers 2 --output outputs/benchmark
```

Параметры: `python -m rockcut.benchmark --help`. Итоги и исходные результаты
создаются в выходной папке; заранее подготовленных результатов в репозитории нет.

## Стратегии поиска

| Стратегия | Особенность |
| --- | --- |
| `baseline` | Ряды, возмущения и L-BFGS для лучших кандидатов |
| `diverse` | Несколько ориентаций рядов и разнообразные старты |
| `repair` | Удаление и повторная вставка группы изделий |
| `adaptive` | Перераспределение весов геометрических нарушений |
| `polish_all` | L-BFGS для всех кандидатов пакета в пределах бюджета |
| `combined` | Разнообразные старты, перестройка группы и адаптивные штрафы |
| `restarts` | Повторные попытки на том же количестве |
| `anneal` | Постепенное уменьшение внутреннего зазора локального поиска |

Валидатор для всех стратегий один. Поиск количества и доводка — отдельные
этапы; перечисленные варианты относятся к поиску.

## Интерпретация результатов

Сравнивайте одинаковые задачи, seed, бюджеты и устройства. Запуски перемешиваются,
каждый процесс прогревается и использует один вычислительный поток.
Сохранённые координаты повторно проверяются независимым 2D-валидатором.
Неудача достижения целевого количества не доказывает его невозможность.
Отдельное время успешного запуска не заменяет сравнение всей серии.

Переносимый набор 3D-слэбов и измерения CPU/CUDA описаны в
[performance/README.md](performance/README.md).
